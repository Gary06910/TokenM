## 我们处理哪些信息

1. **账户标识。** 云函数从当前微信调用上下文取得 OpenID 与 AppID，用于创建仅属于当前用户的内部账户标识、隔离数据和发送订阅消息。OpenID 只保存在拒绝客户端直读的 `users` collection，不返回小程序页面或 Desktop。
2. **电脑绑定与安全信息。** 处理用户设置的电脑名称、随机 desktop ID、绑定/解绑状态、credential 的服务端 HMAC 摘要、创建时间、最后在线时间与最后任务上报时间。plaintext device credential 只在成功配对响应中出现一次；服务端不保存明文。
3. **任务元数据。** 处理 event ID、匿名 session ID、完成时间、隐私模式标记、通知状态和用于幂等/安全校验的摘要值。任务记录与通知额度相互独立。
4. **订阅授权与额度状态。** 处理一次性订阅 grant intent、用户回传的 `accept/reject/ban/filter` 结果、可用/保留/已消耗额度以及微信发送结果码。内部额度是体验账本，微信发送接口仍是授权是否可用的最终判断。
5. **安全与运行数据。** 处理截断/哈希后的请求或设备标识、速率限制计数、机器错误码和安全事件。安全日志不记录完整 IP、OpenID、配对码、Authorization、prompt、summary 或调用堆栈。

Token M 不请求微信头像、昵称、手机号、位置、通讯录或微信聊天记录。

## 隐私模式与完整模式

**隐私模式默认开启。** 仅上传完成事件、电脑标识、匿名会话标识、完成时间和隐私模式标记，可选用户设置的匿名项目别名。隐私模式明确不上传 prompt、完整对话/完整历史、工作目录、源代码、文件内容、环境变量转储、Codex 最终回复或其他 turn 内容；服务端收到这些字段会拒绝请求，不会静默保留。

**完整模式只能由用户在 Desktop 主动开启。** 可额外上传项目 basename/用户别名、模型、最多 600 字符的单段任务结果摘要和耗时。完整模式仍不上传 prompt、完整聊天记录、工作目录或源代码。请只在接受这些字段进入云端时开启。

微信通知在隐私模式只使用通用完成文案、完成时间和可选电脑名，不包含项目、模型或摘要。我们不承诺微信通知一定送达；只有微信接口明确返回成功才记为已发送。

## 使用目的

- 建立当前微信用户与已绑定 Desktop 的一对一关系；
- 保存并展示用户自己的 Codex 完成记录；
- 在用户主动取得一次性订阅授权且额度可用时发送一条完成提醒；
- 防止配对码猜测、credential 滥用、重复事件与重复扣减；
- 响应清除历史、解绑电脑和删除账户请求；
- 进行最小化的故障诊断、速率限制和安全审计。

不会把上述数据用于广告画像、出售给第三方或多人共享 Desktop。小程序没有公共用户目录或管理员客户端接口。

## 存储位置与服务提供方

业务数据存放在部署者为本小程序配置的腾讯云开发 CloudBase 环境；订阅消息由微信服务端处理与投递。部署者应在微信后台披露真实主体、实际地域和相关第三方处理信息，并只让必要的维护人员访问控制台。AppSecret、CloudBase secret、pepper 与 device credential 不进入小程序前端。

## 保留期限

- task 与 notification delivery 默认保留 90 天，部署者可按披露内容缩短或明确调整；默认不得无限期保留。
- 失效 pairing session 在过期 24 小时后清理；是否仍有效始终按实时 TTL 判断，不取决于后台清理是否已经运行。
- subscription grant 终态默认保留 30 天；过期 prepared grant 在 24 小时后清理。
- security event 与 rate-limit 数据默认保留 30 天（过期 rate-limit bucket 可更早清理）。
- active 账户与 active desktop 在用户使用期间保留；解绑后 credential 立即失效，历史 task 按上述期限或用户清除请求处理。
- provider 结果为 `unknown` 时 reservation 暂时保留，直到有明确 reconciliation 结果；不会为释放额度而自动重发通知。

部署者如修改期限，必须同步修改环境配置、产品内说明和微信后台隐私指引。

## 安全措施

所有小程序业务读写通过云函数，九个业务 collection 对小程序客户端默认拒绝直读直写。云函数每次从微信上下文解析身份并校验 ownership；Desktop 使用 HTTPS bearer credential，服务端只保存独立 pepper 的 HMAC。配对码 10 分钟失效、一次性使用，并受全局与会话速率限制。事件使用稳定 ID、canonical digest 与事务防止重复保存、重复发送和额度负数。日志按 allowlist 记录并对 secret 扫描。

## 用户控制、清除与删除

- **关闭任务通知：** 在设置关闭后，未来任务仍会保存，但不会尝试发送微信提醒。
- **解绑电脑：** 在电脑列表选择解绑并二次确认。服务端立即把 desktop 置为 revoked 并清除 credential hash；该 credential 的下一次请求立即失败。解绑本身不删除已有 task。
- **清除任务记录：** 在“设置 → 数据与隐私 → 清除任务记录”输入明确确认。服务端先写入 `historyClearedAt`，提交后旧 task 对查询立即不可见；后台按有限批次物理删除 task 与对应 delivery。响应中的 `cleanupPending=true` 表示物理清理仍在继续，不表示旧记录仍可见。
- **删除账户：** 在“设置 → 数据与隐私 → 删除账户”输入明确确认。服务端首先把账户置为 deleting、撤销全部 desktop 并拒绝后续业务读写，再分批删除 task、delivery、grant、pairing、notification state 与用户身份数据。删除量可能超过一次云函数执行上限，因此物理清理可以异步分批完成。
- **联系处理：** 若无法进入小程序，请通过 `<请填写联系方式>` 提交访问、更正或删除请求；部署者应核验请求人与账户关系，并告知处理状态。

清除或删除完成后不可恢复。任何“已删除”表述都应区分立即不可见/credential 立即撤销与后台物理清理完成状态，不作超出实际系统能力的承诺。

## 变更通知

处理目的、数据类型、保留期限、服务提供方或联系方式发生实质变化时，部署者应先更新本说明和微信后台隐私指引；如平台要求重新取得同意，应在继续调用相关隐私能力前完成。不会以静默开启完整模式的方式扩大上传范围。
